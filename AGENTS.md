# AGENTS.md

## Project Overview

This repository is a prototype 2D obstacle-dodge driving game built with the
Usagi game engine in Lua.

Core concept:

- The player controls a car positioned near the bottom of the screen.
- The car dodges incoming obstacles.
- The road/background scrolls downward to simulate the car moving forward.
- The prototype should prioritize responsive controls, readable collision, and a
  clear sense of speed over visual polish.

## Engine And Language

- Engine: Usagi
- Language: Lua 5.5
- Primary docs:
  - Local: `USAGI.md`
  - Online: https://usagiengine.com/
- Entry point: `main.lua`
- API stubs: `meta/usagi.lua`

Use the local `USAGI.md` and `meta/usagi.lua` files first when checking API
details. They are generated by the installed Usagi version for this project.

## Run Commands

- Start live-reload development:
  - `usagi dev`
- Run without live reload:
  - `usagi run`
- Refresh local docs and stubs after updating Usagi:
  - `usagi refresh`
- Export builds:
  - `usagi export`

Do not assume Usagi is installed globally. If a command fails because `usagi` is
missing, report that clearly instead of replacing the engine workflow.

## Usagi Project Conventions

- Keep `main.lua` as the game entry point.
- Use Usagi lifecycle callbacks:
  - `_config()` for game metadata and engine config.
  - `_init()` for initial game state.
  - `_update(dt)` for simulation and input.
  - `_draw(dt)` for rendering.
- Store cross-frame mutable game state in a capitalized global, usually `State`.
- Keep file-scope constants in `SCREAMING_SNAKE_CASE`.
- Use `snake_case` for local variables, functions, and table fields.
- Use 2-space indentation for Lua.
- Prefer Usagi action input such as `input.LEFT`, `input.RIGHT`, `input.UP`,
  `input.DOWN`, and `input.BTN1` for gameplay controls.
- Draw in game-space pixels. The default Usagi resolution is 320x180 unless
  `_config()` overrides it.

## Prototype Design Direction

Favor a small, complete arcade loop:

- Player car:
  - Fixed near the bottom of the screen.
  - Moves left/right first; add vertical movement only if it improves dodging.
  - Clamp movement to the road bounds, not necessarily the full screen.
- Background:
  - Scroll visual road markings, lane lines, or tiles downward.
  - Use a scroll offset accumulated from `dt`.
  - Wrap repeated background elements when they leave the screen.
- Obstacles:
  - Spawn above the top edge.
  - Move downward at the current game speed.
  - Despawn after leaving the bottom edge.
  - Use simple rectangles or sprites while prototyping.
- Difficulty:
  - Increase obstacle spawn rate and/or scroll speed gradually.
  - Keep tuning constants near the top of the file.
- Collision:
  - Use simple axis-aligned rectangles unless there is a clear need for a more
    complex shape.
  - Keep collision boxes readable and forgiving.
- Game states:
  - Start with `playing` and `game_over`.
  - Restart should reset `State` through a small helper called by `_init()` and
    by the restart input.

## Code Organization Guidance

The prototype may stay in `main.lua` while it is small. Split into modules only
when the file becomes hard to scan or the behavior has stable boundaries.

Reasonable future modules:

- `player.lua`
- `road.lua`
- `obstacles.lua`
- `collision.lua`

When adding modules, use stock Lua `require`, for example:

```lua
Player = require("player")
```

## Rendering Guidance

- Start with Usagi primitive drawing (`gfx.rect_fill`, `gfx.line`,
  `gfx.rect`, `gfx.text`) before adding sprite assets.
- Use a restrained pixel-art style that reads clearly at 320x180.
- Keep the car, road bounds, obstacles, and UI visually distinct.
- Avoid decorative effects that make collision or lane position ambiguous.
- If adding sprites, use `sprites.png` with the configured Usagi sprite size.

## Verification

Before considering gameplay changes done:

- Run or attempt `usagi dev` or `usagi run` from the project root.
- Check that the game starts without Lua errors.
- Check that the car remains within bounds.
- Check that scrolling wraps cleanly.
- Check that obstacles despawn.
- Check that game-over and restart behavior work when present.

If Usagi cannot be executed in the environment, note the exact command attempted
and the failure.

## Editing Rules For Agents

- Keep changes focused on the requested gameplay or tooling task.
- Do not rewrite generated files such as `USAGI.md` or `meta/usagi.lua` unless
  the task is specifically to refresh Usagi docs/stubs.
- Do not introduce another framework or engine.
- Do not replace the Lua/Usagi workflow with Love2D, Pico-8, JavaScript, or a
  browser canvas prototype.
- Prefer clear constants and small helper functions over broad abstractions.
- Preserve user changes in the working tree. Do not revert unrelated edits.
